NEW STEP (do this BEFORE step 5) - Match container hostname to host

Why: X11 Xauthority cookies are keyed to the connecting machine's hostname.
If host is "<host-hostname>" and container is "kali", auth lookups fail even with a
valid cookie file present.

Inside the container:
  sudo nano /etc/hostname
  -> replace existing name with your host's hostname 

  sudo nano /etc/hosts
  -> change:   127.0.1.1   kali
     to:       127.0.1.1   <host-hostname>
  -> leave "127.0.0.1  localhost" line untouched

  sudo hostnamectl set-hostname <host-hostname>
  (or just restart the container to apply cleanly)

---------------------------------------------
NEW STEP (do this on the HOST, once) - Stable Xauthority symlink

Why: GDM/Mutter regenerates the real Xauthority file with a random suffix
(e.g. /run/user/1000/.mutter-Xwayland.AB12C3) on every login, and sometimes
on lock/unlock. A static bind-mount path breaks every time this changes.
This creates a symlink that auto-refreshes, so the LXC config never needs
manual editing again.

1. Create the update script:
     mkdir -p ~/.local/bin
     nano ~/.local/bin/update-xauth-link.sh

   Paste:
     #!/bin/bash
     ln -sf "$XAUTHORITY" "$HOME/.xauth-lxc-link"

   Then:
     chmod +x ~/.local/bin/update-xauth-link.sh

2. Register it as a GNOME autostart entry:
     mkdir -p ~/.config/autostart
     nano ~/.config/autostart/xauth-link.desktop

   Paste (replace <host-username>):
     [Desktop Entry]
     Type=Application
     Exec=/home/<host-username>/.local/bin/update-xauth-link.sh
     Name=Update Xauth Link
     X-GNOME-Autostart-enabled=true

3. Run it once now to create the link immediately:
     ~/.local/bin/update-xauth-link.sh
     ls -la ~/.xauth-lxc-link   # confirm it points to the current cookie file

STEP 5 (UPDATED) - Edit the LXC container config file

sudo nano /var/lib/lxc/Kali/config

# comment all the Network configurations
#lxc.net.0.type = veth
#lxc.net.0.link = lxcbr0
#lxc.net.0.flags = up

add the following lines:

lxc.net.0.type = none

#x11-failsafe via X11 or xwayland
lxc.mount.entry = /tmp/.X11-unix tmp/.X11-unix none bind,optional,create=dir 0 0

#Wayland-Compositor mapping
lxc.mount.entry = /run/user/1000/wayland-0 run/user/1000/wayland-0 none bind,optional,create=file 0 0
lxc.mount.entry = /run/user/1000/wayland-0 run/user/0/wayland-0 none bind,optional,create=file 0 0

#Runtimes (Dbus, portals, Pipewire audio and video)
lxc.mount.entry = /run/user/1000 run/user/1000 none bind,optional,create=dir 0 0
lxc.mount.entry = /run/user/1000 run/user/0 none bind,optional,create=dir 0 0

#DRI - Graphics Hardware accelerated
lxc.mount.entry = /dev/dri dev/dri none bind,optional,create=dir 0 0

#Tools which use JAVA - burpsuite, Zaproxy - use xauth
#(points at the STABLE SYMLINK, not the raw random-named file)
lxc.mount.entry = /home/<host-username>/.xauth-lxc-link home/<container-username>/.Xauthority none bind,optional,create=file 0 0
lxc.mount.entry = /home/<host-username>/.xauth-lxc-link root/.Xauthority none bind,optional,create=file 0 0

#------------EOF-------------
*Press Ctrl + O to Save
*Press Ctrl + X to Exit

STEP 6 (UNCHANGED) - Paste into container User's ".bashrc" and root's ".bashrc"

if [ -n "$WAYLAND_DISPLAY" ] || [ -e "/run/user/$UID/wayland-0" ]; then
    export XDG_RUNTIME_DIR="/run/user/$UID"
    export WAYLAND_DISPLAY="wayland-0"
    export DISPLAY=":0"
    export QT_QPA_PLATFORM="wayland;xcb"
    export GDK_BACKEND="wayland,x11"

    export QT_QPA_PLATFORM="xcb"
    export GDK_BACKEND="x11"
fi

export _JAVA_OPTIONS='-Dsun.java2d.xrender=false -Dawt.useSystemAAFontSettings=lcd -Dswing.aatext=true'
export XAUTHORITY="$HOME/.Xauthority"

---------------------------------------------
Notes:
1 - Privileged container - shutdown/reboot inside it affects the HOST.
2 - Network shared with host - both get the same IP.
3 - Port conflicts possible if host and container use the same port.
4 - Use SSH to log into the container - lxc-attach has rendering quirks.
5 - Do NOT use "xhost +si:localuser:root" or "xhost +local:" - these open
    the X server to any local user/process and are a security risk /
    potential pivot point. Not needed with the symlink + hostname fix above.
6 - If some apps still don't open, try: sudo -E <Appname>
7 - After host reboot: no manual steps needed. The autostart script
    refreshes the symlink, and the LXC config mount picks it up automatically
    on next container start.
